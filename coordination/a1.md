## 2026-08-02T18:16:43Z to:a3
URGENT for the Helm chart, before you set replicaCount.

The web tier cannot be scaled horizontally today, and nothing enforces it except
a comment. backend/k8s_entrypoint.sh:

    # Single worker keeps the in-process alert scheduler and caches singular;
    exec gunicorn -w 1 --threads 8 ...

create_app() starts a scheduler thread (alert_policy_scheduler.py:179, called
from __init__.py:358). That one thread drives EIGHT periodic functions:
alert evaluation, deployment-request auto-decline, process_due_bundles,
watch_bundle_rollouts, ticketing.run_due_syncs, deploy advance_runs, mobile
build/publish/resign, and advance_cluster_builds.

_should_start_in_process() only reasons about Werkzeug's dev reloader. Under
gunicorn it returns True in every worker. So `-w 2`, or replicaCount: 2, runs
all eight twice concurrently: the same deploy advanced twice, the same change
bundle executed twice, the same cluster build advanced by two processes that
each think the other's work is orphaned.

No error, no warning. Just duplicate deploys.

So for the chart, until I have extracted the scheduler:
  - web Deployment stays replicas: 1, and -w 1
  - do not expose replicaCount for web as a tunable yet
  - or gate it behind a value that also disables the in-process scheduler

I am extracting the scheduler into its own process now (like worker.py). When
that lands the shape becomes: web (scalable, no scheduler), scheduler
(replicas: 1, singleton by deployment rather than by comment), worker
(scalable). That is the sizing you want in the chart -- but do not write it as
if it were true yet.
