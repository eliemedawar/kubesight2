Cluster Builder

The tab is built around the build — an event that starts, ends, and leaves a receipt. It should be built around the machines and the cluster, which persist. A build is only the transition between those two states.

Today
Builds · New build · Infrastructure.
Credentials are a settings dump, a finished build is a dead receipt, and a failure is the end of the road.
→
Proposed
Fleet · Reach · New build.
Reach is a live property of machines, a finished build keeps growing, and a failure is a state you continue from.

Why the shape glyph earns its place. Circle is a load balancer, red is a control plane, square is a worker; filled means joined. The anti-affinity warning belongs here, not in preflight. It is knowable the instant the second control plane is assigned, and it is cheapest to fix while you are still looking at the list of machines. Preflight keeps the hard block; this is the same fact delivered early enough to act on cheaply.

Rebuild

Every choice that made this cluster is still recorded — machines, versions, CIDRs, mirror and SSH route. Next year's rebuild starts from a filled-in form, not a blank one.

Why this belongs in Cluster Builder and not Clusters. The Clusters page speaks Kubernetes — namespaces, workloads, health. This page speaks machines — vCenter VMs, ESXi hosts, SSH routes, disks. Adding a worker is a machine job, so it lives with the machines.

What changes, and what deliberately doesn't

Keep
The shape glyph, the phase rail, the dark log well, the severity-first preflight.

These already work and are already built. The concept leans on them harder rather than replacing them — the glyph in particular becomes the spine that ties all six screens together.

Reframe
Infrastructure becomes Reach.

Same four records, inverted presentation: the screen answers "can we get to the machines" and keeps the forms behind that answer. The path diagram and the per-machine matrix are new; the CRUD underneath is not.

Reframe
Builds becomes Fleet.

Finished builds stay on the page as managed clusters instead of collapsing into a link. Drafts, in-flight builds and living clusters share one grid because they are the same object at three ages.

New
Failure diagnosis, preflight diff, and "where do I fix it" labels.

Three small additions aimed at the same thing: turning a report of what is wrong into an instruction about what to do next, and who does it.

New
Day 2 — add, drain and replace a worker.

Already scoped in the plan and already reachable through the API design. This is the screen it needs. It is also the largest piece of real work in the concept.

Unchanged
Every safety property.

Log scrubbing, the warning acknowledgement gate, hard failures that cannot be waved through, encrypted secrets that are never rendered back, and the separation of create from execute so a reviewer can gate the run.
